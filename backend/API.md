# API Documentation

Base path: `/api/v1`. Interactive docs are also auto-generated by FastAPI at `/docs` (Swagger) and `/redoc` — this file is the hand-written reference for humans and for endpoints those tools don't explain well (auth flow, error semantics, business rules).

## Auth

All endpoints require a Supabase Auth JWT:

```
Authorization: Bearer <supabase-jwt>
```

The token is verified in `core/security.py`, mapped to a PM row via `get_current_pm` (`api/v1/dependencies.py`). If the token is valid but no PM row matches the `auth_id`, the request fails with `404 PM not found` — this can happen for a Supabase user that hasn't been provisioned as a PM yet.

`require_admin` additionally checks `PM.is_admin` and returns `403 Admin access required` if false. **Not currently applied to any route** — see Gaps below.

## Error format

Errors follow FastAPI's default shape:

```json
{ "detail": "Task not found" }
```

| Status | Meaning |
|---|---|
| 401 | Missing/invalid bearer token |
| 404 | PM not found (auth) or resource not found |
| 409 | Conflict — e.g. task already claimed by another PM |
| 403 | Caller lacks admin rights (reserved for admin-only routes) |

## Tasks — `/tasks`

### `GET /tasks`
List all tasks.

- Auth: any authenticated PM.
- Response: `200`, array of `Task`.

### `GET /tasks/{task_id}`
Fetch one task by id.

- Auth: any authenticated PM.
- Response: `200` `Task`, or `404` if not found.

### `POST /tasks/{task_id}/claim`
Self-assign an `unassigned` task to the calling PM.

- Auth: any authenticated PM.
- Concurrency: uses an atomic conditional update (`UPDATE ... WHERE status = 'unassigned'`) so two PMs racing to claim the same task can't both succeed.
- Response: `200` updated `Task`, or `409` if the task was already claimed (by anyone, including a re-claim by the same PM after it's no longer unassigned).

### `Task` shape (`models/task.py`)

Fields mirror the columns in the supplier-schedule table each email delivers, plus internal bookkeeping fields.

```json
{
  "id": 1,
  "supplier_name": "string",
  "resource": "string",
  "resource_start": "2026-08-16",
  "resource_end": "2026-08-30",
  "hours_allocated": 40.0,
  "project_number": "string",
  "task_number": "string",
  "pm": "string | null",
  "resource_manager": "string | null",
  "project_status": "string | null",
  "project_country": "string | null",
  "remote_onsite": "string | null",
  "brand": "string | null",
  "po": "string | null",
  "sow": "string | null",
  "rate_type": "string | null",
  "status": "assigned | unassigned",
  "assigned_pm_id": "int | null",
  "source_email_id": "string",
  "created_at": "2026-08-16T00:00:00Z",
  "updated_at": "2026-08-16T00:00:00Z"
}
```

Note the two different "status" concepts: `project_status` is free text carried over verbatim from the email (e.g. "Active", "On Hold"); `status` (`assigned`/`unassigned`) is this app's own claim-workflow state, unrelated to `project_status`.

Dedupe key for the "email references existing task → overwrite" rule (CLAUDE.md rule 3) is confirmed as **`project_number` + `task_number`** together (`repositories/task_repository.find_by_project_and_task_number`).

## PMs — `/pms`

### `GET /pms/`
List all PMs.

- Auth: any authenticated PM.
- Response: `200`, array of `PM`.

### `GET /pms/{pm_id}`
Fetch one PM by id.

- Auth: any authenticated PM.
- Response: `200` `PM`. (Note: `pm_service.get_pm` doesn't currently raise/convert a not-found case to `404` the way `tasks.get_task` does — worth confirming behavior when `pm_id` doesn't exist.)

### `PM` shape (`models/pm.py`)

```json
{
  "id": 1,
  "email": "pm@example.com",
  "auth_id": "supabase-auth-uuid",
  "is_admin": false,
  "name": "string | null",
  "created_at": "2026-08-16T00:00:00Z | null"
}
```

## Sync — `/sync`

### `POST /sync/emails`
Triggers a scan of the shared mailbox: fetches new messages via Microsoft Graph, parses each email's task table into one or more `ParsedTaskRow`s, and creates/overwrites task records accordingly (`services/email_service.sync_new_emails`).

- Auth: currently any authenticated PM — **open decision**, may become admin-only (see Gaps).
- Intended caller: an external scheduler (e.g. a cron job) hitting this endpoint, since there's no in-process scheduler.
- Response: `200`, shape returned by `email_service.sync_new_emails()` (recommend documenting the concrete return type once finalized — e.g. count of tasks created/updated, list of errors per email).

## Gaps / suggested next endpoints

These aren't implemented yet but are implied by the models or by the CLAUDE.md conventions — flagging so documentation and implementation stay in sync as they land:

- **`POST /tasks`** — `TaskCreate` model exists but there's no router path that accepts it directly (task creation currently only happens indirectly via `/sync/emails`). Confirm whether manual task creation should be exposed at all.
- **`PATCH /tasks/{task_id}`** — `TaskUpdate` model exists but is unused by any router. Needed if PMs should be able to edit status/assignment outside of claiming.
- **`POST /sync/emails` admin restriction** — CLAUDE.md lists this as an open decision; once resolved, apply `require_admin` here if it should be admin-only.
- **`GET /pms/{pm_id}` 404 handling** — align with `tasks.get_task`'s explicit `HTTPException(404)` pattern once confirmed.
- **Pagination / filtering on `GET /tasks`** — currently returns all tasks unfiltered; likely needed once task volume grows (e.g. `?status=unassigned`, `?project_number=`, `?resource=`).
- **Health check endpoint** (e.g. `GET /health`) — useful for Cloud Run / uptime checks given the stateless, scale-to-zero deployment model mentioned in CLAUDE.md.
- **HTML/plain-text email table parsing** — `services/parser.py` still raises `NotImplementedError` for both content types; needs real sample emails to confirm table structure before it can populate `ParsedTaskRow`.
- **Matching `row.pm` to a PM record** — `task_service.upsert_task_from_row` currently assumes `row.pm` is an email address and looks it up via `pm_repository.get_by_email`. Confirm the email table actually puts an email (not a display name) in the `pm` column.
